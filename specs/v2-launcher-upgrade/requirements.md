# DSH Web Launcher 2.0 需求

## 目标

将当前以单窗口、手工坐标布局为主的启动器升级为完整的 Windows 桌面应用：状态驱动的首页、独立设置页、版本信息、启动器自动检查更新、用户确认后安装更新，以及可预测的关闭/系统托盘行为。

本需求只描述启动器本身，不改变 DSH Web、`.dsh` 会话、凭据或用户工作区的所有权和数据格式。

## 已确认的产品决策

- UI 从现有 WinForms 迁移到 WPF；运行逻辑与 DSH 数据边界保留。
- 关闭窗口时默认弹出选择框：最小化到系统托盘或直接退出。
- 关闭选择框支持“始终如此”；选择结果可在设置中修改。
- DSH Web 启动成功后默认自动打开浏览器，但提供开关。
- 启动器启动时允许自动检查启动器更新；下载和安装必须由用户明确确认。
- 首发发布 x64；代码和运行时抽象不绑定 x64，后续可增加 ARM64 构建。

## 用户故事

1. 作为普通用户，我希望打开软件就能知道 DSH 是否已安装、服务是否运行、当前版本是什么。
2. 作为普通用户，我希望只看到当前状态下有效的主要操作，不必在“启动、停止、打开网址”之间猜测。
3. 作为普通用户，我希望在不停止 DSH Web 的情况下关闭启动器，或选择让启动器留在托盘。
4. 作为维护者，我希望启动器能检查 GitHub 最新版本，并在安装前展示版本号、更新说明和进度。
5. 作为维护者，我希望更新失败时旧版本、工作区和 DSH 会话仍然可用。

## 验收标准（EARS）

### 状态与操作

- 当启动器打开时，系统应先异步检测 DSH 安装状态、受管进程状态和 HTTP 健康状态，再呈现状态对应的操作。
- 当 DSH 未安装时，首页应只将“安装 DSH”作为主要操作，并显示安装进度和日志入口。
- 当 DSH 已安装且服务停止时，首页应将“启动 DSH Web”作为唯一主要操作。
- 当服务正在启动或停止时，系统应禁用会造成重复进程或重复请求的操作，并显示当前阶段。
- 当 HTTP 健康检查成功时，首页应将主要操作切换为“打开 DSH Web”，并提供“停止”次要操作。
- 当端口被未知进程占用时，系统应拒绝停止或替换该进程，并提供修改端口、重试和日志入口。

### 关闭与托盘

- 当关闭行为为“每次询问”时，用户点击关闭应看到“最小化到托盘”和“退出启动器”两个明确选项，并看到“始终如此”复选框。
- 当用户勾选“始终如此”并选择行为后，后续关闭应直接执行该行为。
- 当用户选择最小化到托盘时，主窗口应隐藏，托盘菜单应提供“打开启动器、打开 DSH Web、停止 DSH Web、退出启动器”。
- 当用户选择退出启动器时，系统应退出启动器但不得因此停止由启动器管理的 DSH Web。
- 当用户在设置中修改关闭行为时，新的选择应覆盖此前保存的“始终如此”决定。

### 设置与版本

- 当用户打开设置时，系统应提供工作区、端口、开机启动、自动打开浏览器、自动检查更新、语言、主题和关闭行为设置。
- 当用户打开关于/更新页面时，系统应分别显示启动器版本、DSH CLI 版本和 Node.js 运行时版本。
- 当 DSH Web 启动成功且自动打开浏览器开关开启时，系统应打开当前健康检查通过的本地 URL。
- 当自动更新检查失败时，系统应保留当前运行能力，只显示可读的检查失败状态。

### 启动器更新

- 当启动器启动且自动检查更新开启时，系统应在后台查询 GitHub Releases，不阻塞首页和 DSH Web 启动。
- 当存在更新时，系统应显示当前版本、最新版本、发布日期和更新说明，并提供“下载并安装”按钮。
- 当用户未明确确认安装时，系统不得替换当前启动器文件。
- 当用户确认更新时，系统应下载 Setup 资产、校验 SHA-256，然后由独立更新进程完成替换并重新启动。
- 当下载、校验或安装失败时，系统应保留可运行的旧版本，并提供重试或手动打开 Release 页面。
- 当更新完成时，系统应保留 `%USERPROFILE%\\.dsh`、选定工作区、`%LOCALAPPDATA%\\DSHWebManager` 中的配置和日志。

### 布局与可用性

- 当窗口宽度或高度变化时，界面应通过 WPF 布局容器重新排布，不得依赖整体画布缩放或固定坐标。
- 当窗口处于窄宽度时，设置项和状态信息应改为纵向堆叠，不得出现文字裁切、按钮溢出或操作区重叠。
- 当用户使用键盘操作时，主要操作、页面导航、关闭弹窗和设置控件应具有可见焦点状态。
- 当系统切换浅色、深色或跟随系统主题时，文本、图标、按钮和鲸鱼标识应保持足够对比度。

## 数据与安全边界

- 不读取、不迁移、不删除 `%USERPROFILE%\\.dsh` 内的会话、账号或凭据。
- 不删除用户选择的 DSH 工作区。
- 只停止启动器记录且经过 PID、启动时间、命令行和 CLI 路径校验的进程。
- 更新源只信任 GitHub Releases 中的预期资产和校验值；安装前必须有用户确认。

## 非目标

- 第一版不做 Windows 服务化、多实例编排、插件系统或复杂账户体系。
- 第一版不承诺 ARM64 安装包；只保持代码层面的可移植性。
- 不把 DSH Web 运行时更新和启动器更新混成同一条流程。
