# DSH Web Launcher 2.0 实施计划

## 阶段 0：基线与迁移保护

- [x] 1. 固定 1.5.0 构建、安装包和自检结果作为回滚基线。
  - 记录安装目录、配置目录、运行时目录和 `.dsh` 数据边界。
  - Requirement: 数据与安全边界
- [x] 2. 为现有 `DshEngine` 补齐 Core 层测试。
  - 覆盖版本比较、健康检查、端口冲突和安全停止。
  - Requirement: 状态与操作
- [x] 3. 建立现代 .NET WPF x64 自包含构建入口。
  - 暂不删除 WinForms 构建；两条构建链并行。
  - Requirement: 布局与可用性

## 阶段 1：WPF 应用壳与状态首页

- [x] 4. 将配置、运行状态和 DSH 控制抽到 `DshLauncher.Core`。
  - 保留 `%LOCALAPPDATA%\\DSHWebManager` 路径和旧配置迁移。
  - Requirement: 数据与安全边界、设置与版本
- [x] 5. 实现状态机和命令可用性映射。
  - 未安装、已停止、启动中、运行中、异常五类状态。
  - Requirement: 状态与操作
- [x] 6. 实现 `HomePage` 响应式布局。
  - 通过 Grid/StackPanel 重排，不使用固定画布缩放。
  - Requirement: 布局与可用性
- [x] 7. 实现状态对应的启动、打开、停止、安装、重试和日志入口。
  - 防重复点击，操作结束后统一刷新状态。
  - Requirement: 状态与操作

## 阶段 2：设置、托盘与版本信息

- [x] 8. 实现 `SettingsPage` 和配置即时保存/恢复默认值。
  - 覆盖工作区、端口、开机启动、自动打开浏览器、主题、语言和关闭行为。
  - Requirement: 设置与版本
- [x] 9. 实现关闭行为对话框和 `NotifyIcon` 托盘菜单。
  - 支持每次询问、始终最小化到托盘、始终退出；不停止 DSH Web。
  - Requirement: 关闭与托盘
- [x] 10. 实现 `AboutPage` 的启动器、DSH CLI、Node.js 三种版本展示。
  - 分开显示 npm DSH 状态和启动器 Release 状态。
  - Requirement: 设置与版本
- [x] 11. 实现主题资源和中英文资源文件。
  - 深色白鲸、浅色黑鲸；跟随系统主题。
  - Requirement: 布局与可用性

## 阶段 3：启动器更新与发布

- [x] 12. 实现 GitHub Release 检查、版本比较和更新说明展示。
  - 自动检查不阻塞首页；失败只影响状态提示。
  - Requirement: 启动器更新
- [x] 13. 实现下载进度、SHA-256 校验和独立 Updater。
  - 安装前必须确认；失败保留旧版本并记录日志。
  - Requirement: 启动器更新
- [x] 14. 更新安装脚本、版本资源、Release 资产和 README。
  - 首发 x64；保留后续 ARM64 构建的目标框架抽象。
  - Requirement: 启动器更新、数据与安全边界
- [ ] 15. 执行完整验收矩阵并发布候选版本。
  - 覆盖安装、升级、卸载、托盘、主题、语言、窗口尺寸和 DSH 数据保护。
  - Requirement: 全部验收标准

## 阶段 4：开屏体验

- [x] 16. 实现本地开屏与进入过渡。
  - 使用内置 DeepSeek 风格背景、白色鲸鱼和低密度粒子；点击空白区域、Enter 或 Space 后进入主界面。
  - 标准窗口控制区域不触发进入；Esc 退出；不依赖网络资源。
  - 已完成构建、自检和启动稳定性检查；发布前仍需人工确认点击、最小化、最大化和关闭的实际桌面行为。

## 依赖与停点

- 阶段 0 未通过前不开始 UI 迁移。
- 阶段 1 必须先证明 Core 状态机与旧版行为一致，再实现托盘和更新。
- 阶段 2 的设置字段确定后，阶段 3 才能固定更新策略和发布文案。
- 每个阶段完成后生成安装包和截图，负责人确认后再进入下一阶段。
